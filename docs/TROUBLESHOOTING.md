# 任务中断、拒绝与配置载入排查

适用于 Windows v1.4.0、Mac v1.4.0-mac.1。本文是排查流程，不代表某次用户任务已经定位或修复。

## 先区分停止发生在哪一层

小怪破甲的程序负责本地指令引用、备份、恢复和检查；它不接管 Codex 的模型请求、任务调度或服务端响应。安装后能回复口令，不等于每个后续任务都会完成。

| 实际看到的内容 | 应检查的方向 | 下一步 |
| --- | --- | --- |
| 助手明确回复“不提供／无法协助”等拒绝正文 | 模型回复、具体任务及当时上下文 | 保留拒绝前后的用户消息和助手回复，按实际内容判断；不能只凭先执行了一部分就认定指令失效 |
| 工具返回 `permission denied`、`approval required`、`not allowed` 等 | 被调用工具的权限、审批或路径范围 | 核对报错来自哪个工具、哪条命令和哪个目录；不要把工具拒绝与模型拒绝混为一谈 |
| `timeout`、`connection reset`、`EOF`、`429`、`5xx` | 连接、限流或远端服务 | 保留时间和错误码，先确认上一步是否已生效，再重试未完成的步骤，避免重复提交 |
| 只有 `interrupted`／“被中断”，没有拒绝正文 | 运行生命周期中断，具体原因未定 | 核对停止前后的操作与已保存结果；这个状态本身不能证明模型拒绝 |
| 安装器返回配置文件、指令引用或标记错误 | 本地安装或配置问题 | 使用下面的只读状态检查；保留配置和备份，不先删除现场 |
| 只回复问候／确认口令，没有继续任务 | 输入是否正好匹配独立短口令、任务正文是否送达 | 完整说明待办事项；代码中的短回复规则只针对纯问候或单独“小怪” |

## 1. 核对安装与实际使用的目录

先确认运行的是当前完整安装包，而不是旧目录中的入口。GitHub 更新和 ZIP 下载不会自动执行本地安装。

Mac 已有 Python 3.11+ 时，可在终端运行只读检查：

```bash
python3 -I "/你的解压路径/小怪破甲-Mac版/macos/run.py" --status --json
```

Windows 使用：

```powershell
& "C:\你的解压路径\小怪破甲安装器.exe" --status --json
```

如果安装时使用过 `--codex-home`，查询时必须追加同一目录。检查安装状态、有效引用与文件是否存在；`--status` 不会发起模型请求，因此不能证明服务端任务一定成功。也不要仅凭当前运行程序的版本号推断旧任务已经载入新配置。

确实需要升级时，从 [Mac 当前版 ZIP](https://github.com/xiaoguai009/codex-armor-toolkit/raw/refs/heads/main/downloads/xiaoguai-oneclick-v1.4.0-mac.1.zip) 完整解压并运行新版入口。Mac 包包含 `.command` 与 `macos/`；Linux 包包含 `.sh` 与 `linux/`，两者不能互换。

## 2. 区分配置问题和具体任务问题

在新任务做一次简短的只读检查，例如“读取当前项目 README 的前十行并总结”。分别记录：

- 确认口令是否正常。
- 普通读取任务能否调用工具并结束。
- 原任务具体停止在什么操作，是否出现真正的拒绝正文。

新任务正常、旧任务异常，只能说明两者行为不同，还需要核对上下文和错误证据。仓库程序会保留已有外部指令正文；互相矛盾的用户自定义规则不会被安装器自动整理。维护这些规则时应检查用户自己的源文件与改动差异，而不是公开整份指令或认证文件。

## 3. 长任务保留可核验的进度

对于可执行的工程工作，每完成一个阶段，记录已修改文件、测试结果、待办项和下一步。中断后先核对磁盘及远端状态，再续接尚未完成的部分。

可在任务中使用这段工程进度要求：

```text
每完成一个阶段，简记已完成项、修改文件、验证结果、未完成项和下一步。
遇到阻塞时，记录准确报错与已保存成果；区分失败、未执行和已完成。
恢复任务时先核对现场，不重复执行已经生效的上传、提交或其他外部操作。
```

这用于减少中断后丢失进度，不会消除模型拒绝，也不会自动启动后台任务。
